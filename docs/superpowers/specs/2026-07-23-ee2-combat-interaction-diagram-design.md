# EE2 招式博弈关系图设计规格

## 目标

在 EE2 战斗玩法页内加入一张可读、可操作、可响应式的招式博弈关系图，整理用户提供的草图，并明确三条进入敌人僵直的路径：招式等级对等、抓主动破绽、触发弱点机制。

该图服务于设计阅读，不模拟具体游戏数值，也不引入气绝值、护甲、击晕等其他游戏的通用状态条。

## 信息结构

关系图位于 EE2 页“一句话定义”之后，作为后续“玩家如何战斗”和“三类僵直入口”的视觉总览。

桌面端从左到右展示四个层级：

1. 玩家选择：招式、走位、防御、闪避、特定手段。
2. 敌人当前状态：出招、收招、可识别破绽、弱点条件。
3. 夺权路径：比、抓、触三种入口。
4. 结果：敌人僵直、玩家有限输出、敌人可读脱离、回到招式博弈。

图中使用颜色、标签和短箭头表达关系，所有路径同时保留文字说明，不能只依赖颜色或线条方向理解。

## 三条路径

### 比：招式等级对等

- 触发：双方招式相交。
- 玩家手段：选择合适的出招时机与招式等级，或使用相杀反制。
- 结果：敌人进入僵直，玩家提前获得输出回合。
- 边界：打断等级与抗打断等级必须稳定、可预测、可反馈；它不是一个共享血条或气绝条。

### 抓：主动破绽

- 触发：敌人进入固定后摇、攻击间隙或可识别的破绽招。
- 玩家手段：走位、闪避、防御和观察敌人收招规律。
- 结果：稳定获得一次基础输出窗口。
- 边界：破绽需要可复盘，不应被随机取消或无提示脱离反复没收。

### 触：弱点机制

- 触发：命中特定弱点、使用指定手段或完成敌人专属条件。
- 玩家手段：弱点打击、特定招式、背向攻击或明确条件。
- 结果：用更高准备成本换取更长僵直或阶段变化。
- 边界：属于敌人个性化入口，不能默认扩展成所有敌人共享的通用计量系统。

## 交互行为

- 默认状态显示完整关系，三条路径均为可读状态。
- “比”“抓”“触”使用语义化按钮，点击后设置当前路径并用 `aria-pressed` 暴露选择状态。
- 选择路径后，高亮该路径的节点、箭头和结果，其余路径降低视觉权重但仍保持可见，避免上下文丢失。
- 选中路径下方显示“触发、手段、收益、边界”四项结构化解释。
- 再次点击当前路径恢复完整关系。
- 支持键盘焦点和 Enter/Space 操作；状态不只通过颜色变化表达。

## 响应式布局

- 桌面端使用 CSS Grid 组织节点与路径，连接线放在独立连接区，避免节点文本与线条重叠。
- 图本体保持稳定的最小高度和节点尺寸，避免交互状态改变布局。
- 中等宽度降低列数和节点间距，但保持同一阅读顺序。
- 移动端改为纵向流程：玩家选择、敌人状态、三条路径、僵直结果、输出与脱离；不强行缩放桌面交叉连线。
- 最小文字字号遵循现有项目提升后的可读性要求，不使用极小注释文字承载关键规则。

## 组件与数据边界

- 新增 `src/app/EE2CombatInteractionDiagram.tsx`，只负责关系图的展示和路径选择状态。
- 在 `src/app/ee2-combat-data.ts` 新增关系图数据类型与三条路径数据，复用现有触发、手段、收益、边界文案，不复制知识库全文。
- `src/app/EE2CombatView.tsx` 只负责在定义区后挂载组件，不把图的交互状态提升到 App 全局。
- `src/styles.css` 新增组件专用样式，复用现有颜色变量和断点，不改变星图或右侧详情面板布局。

## 测试与验收

- 组件测试验证：默认显示图标题、四段结果链、三条路径按钮和路径说明。
- 组件测试验证：依次点击“比”“抓”“触”后，按钮的 `aria-pressed`、当前说明标题和高亮路径标记同步变化；再次点击恢复默认状态。
- 回归测试验证：EE2 页面不出现“气绝、稳定值、击晕、护甲”等误归属机制词。
- 类型检查、全量 Vitest、`git diff --check` 和生产构建必须通过。
- 浏览器复核桌面和移动端：没有节点或连线重叠，路径切换可见，移动端按纵向顺序完整阅读，控制台无应用错误。

## 非目标

- 不把关系图改造成可计算伤害的战斗模拟器。
- 不增加共享的气绝、护甲、击晕、稳定值或其他隐藏计量条。
- 不修改概念星图的数据模型、右侧详情三段结构或其他战斗分析页的鬼泣资料。
